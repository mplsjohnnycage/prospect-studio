# Prospect Studio — Headless Agent Control Plane (implementation draft)

**Status:** reviewed source branch only; not deployed, not production verified. This document describes the implemented contract and its remaining gates. It does **not** authorize spending, outreach, publication, or release.

## Goal

A CLI agent, MCP client, hosted orchestrator, or desktop/cloud sandbox can drive the same authorized operations **without launching the Vercel UI**. The UI is optional for visibility and owner decisions; it is not the job runner.

- Vercel / Next.js: optional human panel, OAuth entry and diagnostics.
- Convex: **only authoritative system of record** for prospects, durable jobs, claims, events, outputs, and owner scope.
- MCP: existing scoped OAuth/API-key endpoint, with all operations implemented through the shared agent tool registry.
- CLI: a thin JSON-RPC Streamable HTTP client of that same MCP service.
- Execution: any authorized worker (Pi, Codex, Claude, Docker Cloud/Sandbox Agent, Rivet actor, Sprite) may claim a job. A worker executes only through its granted capabilities.
- Independent verification: separate **trusted backend** decision after evidence is submitted. Worker success is not verification; verification is not human acceptance.
- Rivet Workflows: candidate durable orchestration runtime on top of the authoritative task record. Durable job transitions already live in Convex; a Rivet binding is **not implemented here**.

## Agent interface

Live MCP endpoint: `https://rightful-elk-426.convex.site/mcp` (existing server).
Use the existing OAuth consent page under `/connect` or request an API key through the authorized signed-in account. Never paste OAuth or Docker credentials into a prompt or a repository.

Scopes are enforced by the existing MCP server: `pipeline:read`, `pipeline:write`. The new shared tools are:

| Tool | Scope | Behavior |
|---|---|---|
| `queue_headless_job` | write | Atomically enqueue a typed job with a client idempotency key |
| `list_headless_jobs` | read | Show bounded recent jobs |
| `get_headless_job` | read | Show one job, evidence and status |
| `get_headless_job_events` | read | Show auditable transitions |
| `claim_headless_job` | write | Issue a server-generated UUID lease and fence a worker |
| `renew_headless_job` | write | Extend an active matching lease, max 12 renewals |
| `submit_headless_job` | write | Submit summary and evidence, **not verification** |
| `fail_headless_job` | write | Release or terminate a failed attempt, max three attempts |

Jobs: `research_business`, `qualify_lead`, `build_demo`, `review_demo`, `draft_outreach`.
The type is a routing/contract name, **not an automatic right** to perform all effects in that category.

## CLI usage (no browser required for daily operations)

```bash
export PROSPECT_MCP_URL=https://rightful-elk-426.convex.site/mcp
# Set PROSPECT_MCP_TOKEN securely in your local environment; do not commit it.
node scripts/prospect-control.mjs tools
node scripts/prospect-control.mjs queue research_business \
  'Verify the public service offerings and site claims with source evidence' \
  '{"prospectId":"<OWNED_PROSPECT_ID>"}' 'research:<OWNED_PROSPECT_ID>:v1'
node scripts/prospect-control.mjs jobs
node scripts/prospect-control.mjs claim codex-worker
node scripts/prospect-control.mjs job '<JOB_ID>'
node scripts/prospect-control.mjs renew '<JOB_ID>' codex-worker '<LEASE_ID>'
node scripts/prospect-control.mjs submit '<JOB_ID>' codex-worker '<LEASE_ID>' \
  'Verified site facts with source references' '["https://example.com/source"]'
node scripts/prospect-control.mjs events '<JOB_ID>'
```

Any client that can use MCP `tools/list` and `tools/call` can use these tools, irrespective of its model or agent framework. The CLI does **not** require access to Vercel project secrets, Convex admin keys, or Docker credentials.

## State and concurrency rules

```text
QUEUED --> LEASED --> SUBMITTED --> VERIFIED
   ^          |                        (trusted verifier only)
   |          +--> QUEUED (failed attempt, retry budget remains)
   |          +--> FAILED (third failure / expired third lease)
   |          +--> LEASED (expired lease reclaimed before attempt limit)
                                    SUBMITTED --> REJECTED (trusted verifier only)
```

- All transitions are atomic Convex mutations. `ownerId` is taken from the authenticated connection, **never** the agent-provided payload.
- A job's `idempotencyKey` is unique within its owner; same key plus different payload is rejected.
- The lease ID is generated by the trusted backend. It is returned only to the claiming caller and is never returned by list/get or included in audit events.
- Lease expiration and worker identity are checked when submitting; expired or stale-worker results are rejected.
- An expired lease may be reclaimed and old claims fenced out. Exhausted leases become failed.
- Evidence submitted by a worker is **unverified** until a trusted verifier, with written notes, records an independent decision. No MCP tool exposes this verifier.
- No tool here sends mail, publishes a site, accepts payment, marks a deal won, or approves irreversible effects.
- Existing prospect-specific guardrails (ownership, top-decile constraints, suppressed contacts, approvals) still apply to actual effects run through the preexisting tools.

## Security boundary

Authentication and authorization are provided by the existing Convex MCP OAuth/API-key service. A write-capable agent is allowed to submit tasks and evidence, not take owner-only decisions. Agent-controlled `workerId` is audit metadata and not a separate security identity; **per-agent cryptographic identity, revocation, budgets, and independently attested worker receipts remain production gates**.

The `reviewerId` on the internal verification function is a trusted backend assertion. Its inequality check against `workerId` is a guard, not a substitute for cryptographically authenticated independent reviewers.

Do not place the Docker Cloud OAuth session, sandbox API keys, or service credentials inside job inputs or evidence. Sandboxes should obtain temporary scoped capabilities from a broker.

## QA and release gates

- Unit and protocol contract tests: `node --import tsx --test src/lib/headless-contract.test.ts scripts/prospect-control.test.mjs`.
- Full repository gates: `npm run verify` and `npm run build`.
- Still required: authenticated live MCP job lifecycle in a non-production environment; two concurrently claiming agents; worker crash before/after external tool effect; lease expiry; output validation; real Docker Cloud Sandbox Agent invocation; locked-down per-agent credentials; independent approval and rollback.
- Preserve current production settings. A passing build is not authorization to merge or deploy; the existing independent-review and release gates remain operative.

## Improvements in priority order

1. Add a capability-aware execution broker and budget admission checks.
2. Add signed per-agent identities, least-privilege scopes, and revocation.
3. Bind Rivet durable workflows to Convex task IDs without duplicating job authority.
4. Add deterministic task-type verifiers and browser-based artifact QA.
5. Add durable workspaces and object-storage manifests with checksums.
6. Add an owner-only headless approval workflow with human authentication, never agent-only self-approval.
7. Add real cold-start, crash/restart and external-effect idempotency integration tests.
8. Optimize prospect selection and demo quality by qualified appointments per unit cost.
